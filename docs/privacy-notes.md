# 개인정보·외부 통신 정리 (안내 문구 작성용 메모)

코드 전수 조사 결과입니다. 이 문서는 사용자에게 보여줄 안내 문구를 쓰기 위한 재료입니다.

---

## 1. 밖으로 나가는 요청 — 전부 3+1가지

### ① 지도 그림 조각 (타일) — CARTO · OpenStreetMap

| 항목 | 내용 |
|---|---|
| 어디로 | `{a,b,c,d}.basemaps.cartocdn.com` (밝은 지도·어두운 지도·컬러 지도), `tile.openstreetmap.org` (OpenStreetMap) |
| 언제 | **기본값이 `내장 벡터 (오프라인)`이므로 평소에는 나가지 않는다.** 사용자가 온라인 지도를 직접 고른 뒤부터, 화면을 옮기거나 확대할 때마다 필요한 조각만큼 |
| 무엇이 전달되나 | 타일 좌표 `z/x/y`(= 지금 보고 있는 **지역과 확대 수준**), 접속 IP, 브라우저 종류(User-Agent), 어느 페이지에서 왔는지(Referer) |
| 무엇이 전달되지 **않나** | 사진 파일, 사진의 정확한 위도·경도 값, JSON, 파일명 |
| 쿠키 | 붙지 않음 (`img.crossOrigin = 'anonymous'`) |
| 캐시 | 브라우저 메모리에 최대 600장, 페이지 닫으면 사라짐 |

> **정직하게 짚어야 할 점:** 나가는 건 좌표값이 아니라 "화면에 보이는 지도 조각"이지만, 그 조각이 곧 **경로가 있는 지역**이다. 즉 지도 서버 쪽에서는 "이 IP가 서울 성수동 근처를 확대해 봤다" 정도는 추정할 수 있다. 게다가 재생 중에는 화면이 경로를 따라 움직이므로, 로그를 이어 붙이면 한 지점이 아니라 **이동 경로의 대략적인 윤곽**까지 드러난다. "아무것도 안 나간다"고 쓰면 거짓말이 된다.
>
> **정밀도:** 타일 한 칸은 z13이면 약 5km, z16이면 약 600m, 최대 확대(z19)면 약 76m다. 확대할수록 정밀해진다.

### ② 사용자가 직접 넣은 타일 서버 (`타일 서버 직접 지정`)

- 기본값은 비어 있음. 값을 넣으면 ①과 똑같은 요청이 **그 서버로** 나감.
- 사내망/자체 호스팅용 기능이라, 넣는 순간 책임이 사용자 쪽으로 넘어간다는 점만 한 줄 안내하면 충분.

### ③ Vercel 방문·성능 통계 — **지도 페이지에서만**

- 로드 위치: `index.html` 인라인 스크립트 → `/_vercel/insights/script.js`, `/_vercel/speed-insights/script.js`
- 조건: 배포 도메인일 때만. `localhost`·`127.0.0.1`·`file://`에서는 아예 로드 안 함.
- **추출기 페이지(`photo-geo-extractor.html`)에는 이 스크립트가 없음.** 사진을 실제로 읽는 페이지에는 통계가 안 붙는다 — 안내에 쓰기 좋은 포인트.
- 수집 항목 (Vercel 공식 문서 기준):
  - 방문 통계: 방문 시각, 페이지 URL·경로, 유입 경로(referrer), 쿼리 파라미터(필터링됨), 대략적 위치(국가·지역·도시), OS·브라우저·기기 종류
  - 성능 통계: Web Vitals 성능 지표, 네트워크 속도(4g 등), 브라우저·OS·기기, 국가
  - 쿠키 안 씀 / IP와 묶어 저장 안 함 / 요청에서 만든 해시로 방문자 구분, **24시간 뒤 폐기**
- 이 서비스의 URL에는 파라미터가 붙지 않으므로 사진 데이터가 URL을 타고 섞여 들어갈 여지가 없음.

### ④ 사이트 파일 자체 (모든 웹사이트 공통)

HTML·JS·CSS·데모 GIF를 Vercel에서 내려받는 접속. 웹서버 접근 기록에 IP가 남을 수 있음. 이건 "웹사이트를 여는 행위" 그 자체라 별도 기능이 아님.

### 그 외에는 **없음** — 확인한 것들

- `fetch` · `XMLHttpRequest` · `WebSocket` · `sendBeacon` 호출 **0건**
- 외부 CDN 라이브러리·프레임워크 **0개** (순수 정적 파일 8개)
- 외부 폰트 **0개** (시스템 폰트만 사용)
- 지오코딩/역지오코딩(좌표 → 주소 변환) API **사용 안 함**
- `navigator.geolocation`(현재 위치 요청) **사용 안 함**
- 서비스워커·오프라인 캐시 **없음**
- 사진 파싱은 인라인 Blob 워커에서만 — 워커 코드도 외부에서 안 받아옴

**요약:** 기본 상태(`내장 벡터 (오프라인)`)에서 지도 페이지가 내보내는 요청은 Vercel 통계 하나뿐이고, 추출기 페이지는 파일 자체를 받아오는 것 말고는 **완전히 0**이다.

## 2. 다루는 개인정보 — 전부 브라우저 안에 머문다

### 읽는 것

- 사진 파일은 **앞부분 64KB만** 읽음. 픽셀은 디코딩하지 않고, EXIF가 들어있는 컨테이너 블록만 훑음.
- 원본 사진은 **손대지 않음** (읽기만).

### 뽑아내는 항목 (`photos-geo.json`)

| 필드 | 내용 | 민감도 |
|---|---|---|
| `path` | 폴더·파일 경로 | **높음** — 폴더명에 사람 이름·여행지·회사명이 들어있는 경우가 많음 |
| `lat` · `lon` · `alt` | 위도·경도·고도 | **가장 높음** |
| `taken` · `tz` · `takenUtc` · `gpsUtc` | 촬영 시각(로컬/UTC), GPS 시각 | **높음** — 위치와 결합되면 생활 패턴이 드러남 |
| `model` | 카메라·폰 모델 | 중간 — **체크박스로 끌 수 있음** |
| `size` | 파일 크기 | 낮음 |

> 핵심: **좌표 + 시각의 조합**이 이 서비스가 다루는 가장 민감한 정보다. 집·직장·자주 가는 곳이 그대로 나온다. 그래서 "안 올라간다"는 사실을 분명히 해주는 게 가장 중요한 안내다.

### 저장·보관

- `localStorage` · `sessionStorage` · `IndexedDB` · 쿠키 **사용 0건**. 코드에 아예 등장하지 않음.
- 새로고침하거나 탭을 닫으면 읽은 내용은 전부 사라짐. 설정값도 안 남음.
- 파일이 디스크에 저장되는 건 **사용자가 버튼을 누를 때만**, 브라우저 다운로드 폴더로.

### 만들어지는 파일 (전부 로컬 저장)

`photos-geo.json` · `photos-excluded.tsv`(제외된 사진 경로+사유) · `photos-errors.ndjson` · `photo-map.png` · 영상(mp4/webm)

### 실제로 남아 있는 위험 — 유출이 아니라 **공유**

만든 JSON·PNG·영상에는 집 근처 좌표가 그대로 들어 있다. 서비스가 유출하는 게 아니라 **사용자가 SNS에 올리는 순간** 공개된다.
`photos-excluded.tsv`에는 좌표 없는 사진의 **파일 경로**가 들어가므로 이것도 남에게 그냥 주면 안 됨.
이 한 줄을 안내에 넣는 게, 열 줄짜리 기술 설명보다 사용자에게 실질적으로 도움이 된다.

## 3. 지금 안내 문구의 문제

> "사진과 JSON은 브라우저 안에서만 처리되며 서버에 업로드되지 않습니다. Vercel에는 접속·성능 정보가 전송될 수 있으며, 온라인 지도(CARTO·OpenStreetMap)를 사용하면 표시 지역을 추정할 수 있는 타일 요청도 해당 지도 서버로 전송됩니다."

사실관계는 정확한데, 비개발자 기준으로 이런 문제가 있다. (기본 배경이 오프라인으로 바뀌었으므로 내용도 손봐야 한다.)

1. **모르는 단어가 4개** — 브라우저 안에서만 처리 / Vercel / 타일 / 표시 지역 추정
2. **한 문단에 세 가지 얘기**가 붙어 있어서 "그래서 안전한 거야 아니야?"의 답이 안 보임
3. **결론이 없음** — 사용자가 뭘 하면 되는지(오프라인 지도로 바꾸기, 영상 공유 조심)가 빠져 있음
4. 좋은 소식(사진이 안 올라간다)과 나쁜 소식(지역은 추정 가능)이 같은 무게로 붙어 있어 둘 다 흐려짐

## 4. 쉽게 풀어 쓰는 원칙 6가지

1. **결론 먼저, 예외는 다음에.** "사진은 안 올라갑니다" → "다만 지도 그림은 받아옵니다" 순서. 반대로 쓰면 불안만 남는다.
2. **용어를 행동으로 번역한다.**
   - EXIF → "사진에 같이 저장돼 있는 촬영 정보"
   - 타일 → "지도 그림 조각"
   - 클라이언트 사이드 처리 → "내 컴퓨터 안에서"
   - Vercel → "이 사이트가 올라가 있는 호스팅 서비스"
3. **"안 한다"에 이유를 한 줄 붙인다.** "안 올려요"보다 "**받을 서버가 아예 없어요**"가 훨씬 믿긴다. 실제로 서버 코드가 0줄이니 사실이기도 하다.
4. **비유로 감을 잡게 한다.** "종이 지도를 펴놓고 그 위에 연필로 선을 긋는 것과 같아요. 종이는 가져오지만, 내가 그은 선은 종이 가게로 돌아가지 않아요."
5. **완전히 끄는 방법을 같이 준다.** `내장 벡터 (오프라인)` 배경 하나로 지도 요청이 0이 된다 — 이건 자랑할 만한 기능이니 안내에 넣는 게 이득.
6. **마지막은 사용자가 할 일로.** "만든 영상엔 집 근처가 그대로 나와요. 올리기 전에 한 번만 확인하세요."

**분량 원칙:** 화면에는 3~4줄만. 나머지는 `자세히 보기`로 접어둔다. 다 보여주면 아무도 안 읽는다.

## 5. 문구 초안 (친근한 대화체)

### A. 화면 상단 짧은 버전 — 3줄

> **사진은 이 컴퓨터를 벗어나지 않아요**
> 사진도, 만든 JSON도 어디로도 올라가지 않습니다. 받아줄 서버가 아예 없거든요.
> 지도도 기본은 **오프라인**이라, 인터넷에서 받아오지 않습니다. 더 자세한 지도를 쓰고 싶어 온라인 배경으로 바꾸면 그때부터 지도 회사에 요청이 나가고, 화면 아래에 무엇이 나가는지 그때그때 알려드려요.

### B. `자세히 보기`를 펼쳤을 때

> **사진은 어떻게 처리되나요?**
> 사진 파일의 앞부분만 살짝 읽어서 촬영 위치와 시각만 꺼냅니다. 사진 자체는 열어보지도, 어디로 보내지도 않아요. 전부 이 브라우저 안에서 끝나고, 탭을 닫으면 읽은 내용도 같이 사라집니다. 저장되는 건 저장 버튼을 눌렀을 때 다운로드 폴더로 가는 파일뿐이에요.
>
> **그럼 밖으로 나가는 건 뭐죠?**
> 기본 상태에서는 두 가지, 온라인 지도를 고르면 세 가지입니다.
> - **지도 그림 (기본 꺼짐)** — 지도 배경은 처음에 **내장 벡터 (오프라인)** 으로 시작합니다. 지도 그림이 프로그램 안에 들어 있어서 인터넷을 쓰지 않아요. 도로와 지명이 나오는 지도를 보려고 온라인 배경으로 바꾸면, 화면에 보이는 만큼의 지도 조각을 지도 회사(CARTO·OpenStreetMap)에서 받아옵니다. 사진이나 좌표를 보내는 건 아니지만, "지금 이 근처를 이만큼 확대해서 보고 있다"는 정도는 지도 회사 쪽에 남을 수 있어요. 언제든 오프라인으로 되돌리면 됩니다.
> - **방문 통계** — 이 사이트가 올라가 있는 호스팅 서비스(Vercel)에 "누가 언제 이 페이지를 열었고 얼마나 빨리 떴는지"가 기록됩니다. 국가·브라우저 종류 정도이고, 쿠키는 안 쓰고 24시간 뒤에 지워져요. 사진과는 아무 상관 없습니다. (사진을 읽는 추출기 페이지에는 이것조차 없어요.)
> - **사이트 파일** — 페이지를 여는 순간 화면을 그리는 파일을 받아옵니다. 어떤 웹사이트든 똑같아요.
>
> **정말 서버로 안 올라가나요?**
> 네. 사진을 받을 서버 자체가 없습니다. 이 서비스는 화면을 그리는 파일 몇 개가 전부고, 계산은 전부 여러분 브라우저가 합니다. 궁금하시면 페이지를 연 다음 인터넷을 꺼보세요 — 기본 상태 그대로 처음부터 끝까지 다 돌아갑니다.
>
> **한 가지만 조심하세요**
> 만든 영상과 JSON에는 집이나 회사 근처 위치가 그대로 담겨 있습니다. 서비스가 흘리는 게 아니라, 그 파일을 남에게 보내거나 SNS에 올리는 순간 공개돼요. 올리기 전에 시작점과 끝점이 어디인지 한 번만 확인해 주세요.

### C. README용 (조금 더 압축)

> **개인정보 안내 — 사진은 이 컴퓨터를 벗어나지 않습니다**
>
> 사진도 JSON도 어디로도 업로드되지 않습니다. 받아줄 서버가 없습니다. 사진 파일의 앞 64KB만 읽어 위치·시각을 꺼내고, 나머지는 전부 브라우저 안에서 끝납니다. 저장되는 파일은 저장 버튼을 눌렀을 때 다운로드 폴더로 가는 것뿐이며, 브라우저에 남는 기록도 없습니다.
>
> 지도 배경은 **기본이 `내장 벡터 (오프라인)`** 이라, 그냥 쓰면 지도 요청도 나가지 않습니다. 밖으로 나가는 건 **방문·성능 통계**(Vercel, 지도 페이지에만 적용. 쿠키 없이 국가·브라우저 수준으로 기록되고 24시간 뒤 폐기)와 **사이트 파일 자체**(모든 웹사이트와 동일)뿐입니다. 온라인 지도 배경(CARTO·OpenStreetMap)으로 바꾸면 여기에 **지도 그림 조각 요청**이 추가됩니다 — 사진이나 좌표가 아니라 화면에 보이는 지역의 지도 이미지이며, 화면에서 무엇이 나가는지 바로 안내합니다.
>
> 다만 만들어진 영상·JSON에는 실제 위치가 그대로 담깁니다. 공유하기 전에 시작점과 끝점을 확인하세요.

## 6. 반영된 변경 (2026-08-26)

- 지도 배경 **기본값을 `내장 벡터 (오프라인)`으로** 변경 (`opts.base`, select 순서, 다크 모드 시작 로직). 다크 테마로 시작해도 더 이상 온라인 타일로 바뀌지 않는다.
- 배경 셀렉트 바로 아래에 **선택에 따라 바뀌는 안내(`#baseNote`)** 추가 — 오프라인이면 "나가는 요청 없음", 온라인이면 무엇이 전달되는지, 직접 지정한 서버면 호스트명까지.
- 내장 벡터 지도의 **날짜변경선 깨짐 수정** — 유라시아·남극·피지·랑겔섬 링이 지도를 가로지르는 가로줄로 그려지던 문제. 링마다 경도를 펼치고(unwrap), 지구를 감는 남극 링은 지도 아래 끝을 따라 닫도록 변경.

- 두 페이지 상단 안내 박스를 **결론 3줄 + `자세히 보기` 펼침** 구조로 교체 (4·5절 원칙 적용). 테두리도 경고색에서 안전색으로.
  - 지도 페이지: "파일은 이 컴퓨터를 벗어나지 않아요" + 나가는 것 3가지 + 공유 주의
  - 추출기 페이지: "사진은 이 컴퓨터를 벗어나지 않아요" — 이 페이지는 지도도 통계도 없어 요청이 0건이라는 점을 전면에
- README 상단 안내 문단 교체 + **`개인정보와 외부 통신`** 절 신설(표 형태), 기본값 변경에 맞춰 주요 특징·문제 해결·지도 타일 출처 문구 수정.
